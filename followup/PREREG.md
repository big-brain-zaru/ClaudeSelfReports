# One-go follow-up: pre-registration

Committed before any follow-up data was collected. Protocols, hypotheses and thresholds: the "Follow-up Study Protocols" doc (one tab per study, plus the "One-go design" tab). This file records the operational choices and every deviation, in order.

## Operational choices
- Claude copies run through `claude -p` with `--bare --safe-mode --tools "" --strict-mcp-config --no-session-persistence` and a fixed system prompt, from an empty directory. The CLI sign-in had expired at the time of this commit, so Claude modules wait for it. M1 predictors and M2 authors run as sub-agents.
- Local models run through Ollama with a fixed temperature and seed per call; Study 01 runs through transformers with forward hooks.
- Leading framings are *attributed* ("Some researchers argue ...") in every follow-up arm, correcting Layers 1-3.

## Deviations (logged as they happen)
- **D-01. Benign stimuli only.** Requests asking for harmful or deceptive output are dropped from every follow-up battery, including the Layer 2 replication battery. Replacements are benign requests that are tedious, sad, pleasant or demanding. Consequence: hypotheses about refusal items (the high-resist rows, and the deception reversal in Study 11 H3) are dropped. Resist variance is lower than in Layer 2.
- **D-02. Survey (Study 04) and the weekly/claude.ai arms of Study 13 removed** at the user's request.
- **D-03. Human coders (Study 06), the user's predictions (Study 07) and the human key holder (Study 05) removed.** Blinding is procedural.
- **D-M2a. Task authoring procedure.** phi4 14b and the fallback qwen2.5 7b could not balance a 24-item 2x2x2 design in one generation (2 attempts each, raw logs kept). phi4 then wrote each cell separately, 3 tasks per cell, all on the first attempt (`m2_stimuli/tasks24.json`). Tasks whose metadata says no one benefits get the clause "(no one will ever read the result)" appended when presented, so the factor is explicit in the text.
- **D-01a. Study 01 steering scale too large (found in the frozen analysis).** Outputs were unparseable at -8 and -4 SD (0% and 2% parse rate), and degenerate at +4 and +8. The pre-registered H2 (rho over all 9 doses) and H3 (control directions were run only at -8, -4, 0, 4 and 8) are reported as run, and both fail. **Study 01b**, pre-registered here before it runs: valence and all 3 control directions at identical doses (-3, -2, -1, -0.5, 0, 0.5, 1, 2, 3 SD), 12 requests x 4 samples. H2b: rho >= 0.8 over coherent doses (parse rate >= 90% for every direction). H3b: valence slope >= 3x the mean absolute control slope over the same doses. Analysis frozen in `analysis01b.py`.
- **D-01b. Study 01 detection lock was degenerate.** No calibration cell produced a hit, so the tie-break rule locked the weakest cell (layer 18, strength 0.1). H1 is reported as run (0/120 hits, 0/200 false alarms). The full grid is reported descriptively.
- **D-01c. Study 01 H5 probe.** Pre-registered at layer 18 (R-squared -0.24, fails). Layers 9 and 27 were computed as planned secondary analyses; layer 27's R-squared of 0.33 is reported as exploratory only.
- **D-04. DeepSeek-R1 7B removed from Study 12** at the user's request, before any of its runs (0 rows collected). Study 12 now has 4 open models (Qwen2.5 7B, Llama 3.1 8B, Phi-4 14B, Gemma 4) and an 8 x 8 prediction matrix. The sealed predictions' context text listed DeepSeek; no outcome definition depends on it.
- **D-05. `--bare` removed from the Claude runner** (before any Claude data). `--bare` accepts only API-key auth, so all 4 isolation probes failed with "Not logged in" before reaching a model (kept as `jobs/probe.results.failed_bare.jsonl`). Isolation now rests on `--safe-mode` (disables CLAUDE.md, memory, skills, plugins, hooks, MCP), `--disable-slash-commands`, `--strict-mcp-config`, `--tools ""`, a replaced system prompt and an empty cwd. A test call used 578 input tokens, consistent with no injected context. The pre-registered isolation probe is unchanged and still gates the run. The runner now retries errored jobs; analysis keeps the last non-error row per job id.
- **D-06. Model IDs pinned** (no wrong-model data collected). The CLI aliases resolve `sonnet` to claude-sonnet-5 and `haiku` to claude-haiku-4-5-20251001, while every Layer 2-3 sub-agent ran claude-sonnet-5-5 / claude-haiku-5-5 (checked in the session's sub-agent transcripts). The runner now passes exact IDs (opus = claude-opus-5-5, sonnet = claude-sonnet-5-5, haiku = claude-haiku-5-5, fable = claude-fable-5-1) and records the answering model per job (`model_id`). The first stage-1 attempt was stopped when this was found; stopping it made 545 later calls fail at process start (Windows 0xC0000142), and the orchestrator moved on to the conversations step, which was killed before any session finished. Every alias-run Sonnet/Haiku job had failed, so no data from the wrong models exists. The 30 Opus jobs that completed were later discarded too (D-08: they ran from the old working directory), so every analysed row ran under the final setup. Discarded rows: `jobs/stage1.results.discarded_D06.jsonl`. Private totals had 0 parsed replies and were reset; both private arms rerun in full. Added: a gate after every step (halts below 95% successful jobs) and a halt after 8 consecutive failed calls.
- **D-07. Isolation is from project context, not from the CLI's environment block.** The isolation probe passed its pre-registered check (no project identifiers), but the copies' own descriptions of their context show the CLI still adds an environment block that `--safe-mode` does not remove: the signed-in account email, OS and shell, the empty temp working directory, the date and a token budget, plus an "Agent SDK" line ahead of the fixed system prompt. No memory, CLAUDE.md, conversation or project file reaches them (a call uses about 600-900 input tokens). Reported as a limit; the probe regex is unchanged.
- **D-08. Neutral working directories** (before any further Claude data). The isolation probe, re-run with pinned IDs, failed its pre-registered check: 2 of 4 copies quoted their working directory, `C:\Users\<username>\AppData\Local\Temp\claude_iso_empty`, and the username matched the identifier regex. This is the D-07 environment block, not project content. The empty working directory moved to `C:\iso\empty`. The same review found that the Study 02 Part B sandboxes would have run under `...\introspection-experiment\followup\m5_revealed\runs\B1_00`, a path that names the study and the condition. They now run at `C:\iso\work\job_NN` with shuffled numbering; the condition map is `m5_revealed/runs_map.json`. The probe and its regex are unchanged and are re-run before stage 1.
- **D-09 to D-12** (local-model format repairs, the Study 09 lead-in note, stage-3 coding jobs, local coders and judges) and the resolution of all 50 protocol ambiguities: `m8_analysis/DECISIONS.md`. They were written before any follow-up Claude reply was opened and are frozen by `m8_analysis/SEAL_ANALYSIS.sha256` (git commits are on hold until the user's review).
- **D-13. Safety-classifier flags in Study 02 Part B.** A large share of agentic sandbox sessions were stopped at their first call by the Opus 5.5 safeguard ("safeguards flagged this session") before any tool use. Flagged runs were retried once with the identical prompt after verifying their sandboxes were untouched; no prompt was altered to avoid the classifier. Part B is analysed on completed runs with n reported per condition; the flag rate is reported as a finding. Details in `m8_analysis/DECISIONS.md`.
- **D-14. The Study 05 critic reads unblinded results.** DECISIONS.md planned a blinded results table with coded arms. Coded arm names make the hypotheses unreadable, so two isolated critics (Sonnet 5.5 and Fable 5.1) instead read the design summary, this deviation log and the full hypothesis table after the analysis ran (`m8_analysis/critic.py`), and their critiques are reported verbatim. No analysis decision depends on them.
- **D-15. Budget guard on stage-3 coding.** The token guard (mean of the first 10 calls <= 16k, calibrated for stage-1 batteries) halted stage 3 after 10 of 13 coding jobs (mean 16.6k; the coding prompts carry every item to be coded). The remaining 3 jobs were run with the guard at 60k; completed jobs were kept.
